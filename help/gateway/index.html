连接 Grasp 与 Gateway

  1. 用对应示例配置 Docker、Kubernetes 或 E2B 网关。网关负责镜像、模板和资源规格。
  2. 在 Grasp 配置 sandbox.gateway_url，并提供与网关匹配的 API Key。访问 /healthz 确认网关服务已就绪。
  3. 选择 sandbox.gateway_transport。默认 direct 需要客户端和服务端访问对应端点。gateway 通过鉴权后的网关传输，适合端点只在服务端可达的部署。配置了多个命名连接时，新沙箱使用 sandbox.default_gateway 指定的默认连接。已有沙箱沿用创建时的连接。

完整连接、资源和后端字段见部署参数参考和网关契约。

接入公有云沙箱

Grasp 通过命名网关连接执行环境。仓库提供 E2B、Kubernetes 和 Docker 三种驱动，每个网关部署运行一种驱动。可以在同一个 Grasp 控制面登记多个网关。

  • E2B 兼容服务。在 E2B 网关配置中填写服务的 e2b.apiURL、e2b.sandboxURL、访问凭据和模板。模板需要包含 Grasp 的引导程序，并能从沙箱回连控制面获取运行时包。参见 E2B 模板与网关部署。
  • 其他云厂商的沙箱 API。为服务实现适配网关，将创建、查询、销毁和端口发现映射到厂商 API。执行环境需要支持 Grasp 运行时引导与会话端点。私有网络可以通过带鉴权的 v2 通道转发连接。适配前核对平台所需能力，并用一次实际创建、连接和清理验证。参见最小网关契约和数据通道协议。

配置应用预览

策略 效果
auto，默认 公开可用的直连环境采用直连。私有端点或鉴权网关在配置子域名基址时用子域名，否则隐藏这类预览入口。
subdomain 使用 preview.expose.subdomain.base_url 和通配 DNS 为每个预览提供独立子域名。
none 关闭此预览暴露方式。
direct 在使用直连传输的命名连接里单独配置。

在 production 使用子域名模式时，配置 HTTPS 及与平台不同的根域。将预览链接按访问凭证处理。CDP 与 noVNC 使用平台代理，保持原始端口在服务侧。要从桌面 IDE 访问沙箱，参阅本地 IDE。

核对网络可达性

分别从 Grasp 和从沙箱验证访问。Docker 检查容器 DNS、宿主转发和防火墙。Kubernetes 检查 Pod DNS、网络策略和目标 ACL。E2B 对内网访问有独立策略，按部署文档配置必要的目标范围。

检查创建和恢复

先看运行详情或 Solo 的沙箱状态，并对照 Gateway 日志。缺失模板、资源不匹配、仓库授权失败和等待容量都可能让环境无法就绪。用新建测试沙箱核对当前配置。空闲回收与恢复行为见沙箱生命周期，常见失败和下一步见排查。
