Help center/Deploy and configure

Connect a sandbox gateway

Set gateway transport, choose a backend, configure preview exposure, and diagnose sandbox startup.

On this page

Connect Grasp and the gateway

  1. Configure the Docker, Kubernetes, or E2B gateway with its example. The gateway owns image, template, and resource selection.
  2. Set sandbox.gateway_url in Grasp and provide the matching gateway API key. Verify that gateway /healthz is ready.
  3. Select sandbox.gateway_transport. The default direct requires callers to reach the relevant endpoints. gateway sends traffic through the authenticated gateway and suits server-only endpoints. With multiple named connections, new sandboxes use the connection selected by sandbox.default_gateway. Existing sandboxes keep the connection they were created with.

See the deployment reference and gateway contract for connection and backend fields.

Connect a public-cloud sandbox

Grasp registers execution environments as named gateways. The repository ships E2B, Kubernetes, and Docker drivers. Each gateway deployment runs one driver, and a single Grasp control plane can register multiple gateways.

  • E2B-compatible services. Configure the provider’s e2b.apiURL, e2b.sandboxURL, credentials, and template in the E2B gateway. The template must include the Grasp bootstrap and reach the control plane to fetch its runtime bundle. See the E2B template and deployment guide.
  • Other cloud sandbox APIs. Implement a gateway adapter that maps create, inspect, delete, and endpoint discovery to the provider’s API. The environment must support the Grasp runtime bootstrap and session endpoint. Private networks can use authenticated v2 transport. Check the required capabilities, then validate an actual create, connection, and cleanup. See the minimum gateway contract and data channel protocol.

Configure app previews

Policy Effect
auto, default Public direct endpoints use direct access. Private endpoints or authenticated gateway transport use subdomains when a base URL is set. Without it, the corresponding exposure option is hidden.
subdomain Use preview.expose.subdomain.base_url and wildcard DNS to give each preview its own subdomain.
none Disable this form of preview exposure.
direct Available on named connections that use direct transport.

For production subdomains, use HTTPS and a root domain separate from the application. Treat a preview URL as an access credential. CDP and noVNC are proxied by the platform, with the raw ports kept on the service side. For desktop IDE access, see Connect a local IDE.

Check network reachability

Verify reachability from Grasp and from the sandbox. For Docker, check container DNS, host forwarding, and firewall rules. For Kubernetes, check pod DNS, network policies, and target ACLs. E2B applies its own private network access policy. Use the deployment guide to configure the required destinations.

Diagnose creation and restore

Start with the sandbox status in Solo or in the run detail, then check gateway logs. Missing templates, resource mismatches, failed repository access, and capacity waits can prevent readiness. Verify current settings with a new test sandbox. See Sandbox lifecycle for reclaim and restore and Troubleshooting for common failures.
